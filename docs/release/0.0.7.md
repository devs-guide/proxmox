## 0.0.7

Release 0.0.7 adds a discovery-led Debian LXC workflow for exposing an
existing, accepted ZFS dataset through a hardened Samba service on a separate
local data network. The Proxmox management path remains the only default route
and administration path, while an independently selected physical DATA-Link
and unnumbered host bridge carry SMB traffic.

The workflow composes host link and bridge management, transactional guest NIC
updates, unprivileged mapped storage access, Proxmox and container firewall
boundaries, one guest-read/authenticated-write Samba share, and revocable
static-destination egress. Site-specific names and addresses are discovered or
confirmed rather than embedded as defaults.

This release consumes an existing accepted ZFS dataset; it does not create or
recreate the pool. Proxy-backed URL brokerage, host addressing on the DATA
bridge, container SSH, whole-GPU passthrough, and Local Model Inventory are
outside this release.

### Highlights

- Preserves the discovered Proxmox management route while building a separate
  physical DATA-Link and unnumbered host bridge for local SMB traffic.
- Adds one static, no-gateway LXC data interface without replacing the existing
  management/egress interface.
- Exposes an existing ZFS mount through one operator-named Samba share where
  guests can read and one selected authenticated account can write.
- Keeps the LXC unprivileged and preserves dataset ownership by translating a
  fixed service identity through ACLs rather than root mapping or mode 0777.
- Applies management/data boundaries through Proxmox firewall policy and a
  default-deny UFW policy inside the container.
- Provides revocable static destination approval for controlled downloads
  without adding another route or enabling general outbound access.
- Validates the actual production parsers, rendered configuration, transaction
  semantics, and Pages dependency graph in pinned GitHub Actions jobs.

### Added

- Physical DATA-Link discovery, ranking, carrier verification, stable MAC/PCI
  identity checks, and explicit activation.
- Canonical untagged or VLAN-aware bridge candidate rendering with checksummed
  backup, warning-aware ifupdown2 validation, apply verification, and rollback.
- Network preflight snapshots that fail closed unless the selected data bridge,
  physical member, host address state, and management route are complete.
- Transactional LXC NIC preview, apply, semantic verification, recovery, and
  ownership-safe rollback.
- Bare IPv4 normalization with configurable prefix, assignable-host checks,
  management/data overlap rejection, and duplicate probing through
  `iputils-arping`.
- Unprivileged-container storage mapping with a locked service UID/GID, access
  ACLs, default ACLs, and optional restartable recursive ACL application.
- LAN-restricted Samba configuration with SMB3, macOS-compatible xattrs, a
  DATA-Link readiness guard, and one guest-read/authenticated-write share.
- Host and guest firewall orchestration, static egress approval/revoke tooling,
  generalized human acceptance evidence, and an issue-to-fix ledger.

### Changed

- Uses compatible native Python on current PVE/Debian lanes before considering
  the legacy managed-CPython fallback.
- Treats feature-owned legacy bridge warnings as repair evidence only; the
  generated replacement must pass both ifupdown2 no-action checks without
  warnings.
- Compares normalized LXC NIC meaning instead of raw PVE field order or
  generated `type` and `hwaddr` fields.
- Sets Proxmox default firewall policy at the supported cluster scope, enables
  node policy separately, and retires conflicting host UFW only after the
  replacement rules validate.
- Uses the Proxmox console or `pct exec` for container administration; the
  accepted Samba role removes and masks container SSH.
- Makes proxy-backed egress future work rather than a 0.0.7 completion gate.

### Fixed

- Fixed a layered-regex defect that parsed the interface method `manual` as
  `ma`; CI now executes the same production parser as the live playbook.
- Fixed candidate rendering that emitted escaped newline text instead of real
  interface records.
- Fixed canonical repair of existing DATA-Link stanzas and rejection of
  duplicate interfaces, bridge attributes on non-bridge stanzas, and
  unrecognized bridge candidates.
- Fixed ifreload diagnostics so warning lines survive normalization and remain
  blocking on generated candidates even when the command exits successfully.
- Fixed late or incomplete data-address validation, including missing ARP
  tooling, subnet/broadcast input, overlap, stale snapshots, and duplicate
  probing immediately before mutation.
- Fixed recursive Ansible variable defaults by separating immutable defaults
  from effective caller-selected paths.
- Fixed false LXC rollback after successful `pct set` by using one production
  parser for update, verification, recovery, rollback, and fixtures.
- Fixed unsupported firewall policy scopes and conflicting host-firewall
  authority with transactional restoration on failure.
- Fixed Samba share nesting, runtime-fact serialization, and boot-time
  convergence around one DATA-Link-bound share.

### Operator workflow and safety

The reviewed workflow is:

1. Discover and confirm the existing management path and a separate physical
   data NIC.
2. Review, write, apply, and verify the host data bridge with out-of-band
   access available.
3. Capture an update-ready network snapshot and add one static no-gateway LXC
   data interface.
4. Map the accepted ZFS mount into the unprivileged LXC and apply service ACLs
   without changing ownership.
5. Apply Proxmox and container firewall boundaries, then configure Samba on the
   data role only.
6. Grant and revoke temporary static egress destinations as needed.
7. Verify routes, addresses, mount access, ACLs, SMB binding and permissions,
   denied traffic, reboot persistence, ZFS health, and real data transfer.

Host network and firewall mutations require out-of-band acknowledgement.
Candidate configuration is backed up and validated before activation. Guest
NIC rollback deletes only a semantically matching feature-owned interface.
Secrets are hidden and removed with the temporary variables file. The managed
Samba configuration does not enable `aio write behind`.

### Human acceptance

Human acceptance completed the management/data separation, warning-free bridge
apply, semantic LXC NIC update, mapped ZFS access, single-share Samba policy,
firewall and egress boundaries, container reboot, full Proxmox host reboot,
and post-reboot revalidation. Mixed-file and large sequential transfers
completed successfully over the separate DATA-Link. These results are
functional evidence, not topology or throughput defaults.
