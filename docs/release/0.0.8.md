## 0.0.8

Release 0.0.8 adds generic, operator-selected LXC-to-LXC rsync and an
on-demand bandwidth test on an existing isolated DATA-Link. It does not assign
source or destination roles and contains no deployment topology.

### Scope

- Release range: `0.0.7..0.0.8`
- Target boundary: authorized rsync and one-shot TCP bandwidth testing on the
  complete selected local DATA CIDR
- Published entrypoints: `setup/lxc/transfer.sh`, `setup/firewall.sh`, and the
  transfer SSH, rsync, and speed-test helpers
- Published runbook: `docs/setup/lxc/transfer.md`

The release does not change Proxmox management networking, add a DATA-Link
gateway, enable administrative container SSH, choose storage paths, manage
Samba availability, or define a backup layout.

### Highlights

- Discovers or accepts an operator-selected static DATA interface and
  canonicalizes its complete network CIDR.
- Applies interface-specific TCP 22 and TCP 5201 policy for that CIDR at the
  container and Proxmox LXC boundaries.
- Runs key-only forced `rrsync` with no shell, PTY, forwarding, tunneling, or
  password login.
- Provides a fixed, shell-free SSH pairing check before any copy begins.
- Runs `iperf3` only when an operator starts a one-shot listener bound to the
  selected DATA address.
- Accepts operator-selected local mount paths and peer-relative paths for
  push or pull without assuming endpoint roles or a directory layout.
- Keeps verification separate and optional.

### Added

- Public-only Ed25519 pairing bundles and pinned peer host keys.
- `proxmox-transfer-ssh check PEER_IPV4` for an explicit key and host-pinning
  handshake with no filesystem operation.
- `proxmox-transfer-speed-test server|client` for a basic multi-stream TCP
  bandwidth measurement.
- `verify-push` and `verify-pull` checksum dry runs.
- Hosted policy coverage for topology neutrality, port binding, publication,
  and the non-deleting rsync contract.

### Changed

- The transfer firewall opt-in now owns TCP 22 and TCP 5201 for the complete
  selected DATA CIDR.
- Samba UFW reconciliation preserves both active transfer rules.
- Source, destination, and storage paths remain runtime operator input.
- Whole-GPU passthrough moves to planned release `0.0.9`; Local Model
  Inventory moves to planned release `0.0.10`.

### Fixed

- Avoids peer-specific `/32` policy and deployment-specific endpoint roles.
- Prevents the supported rsync interface from accepting deletion or
  source-removal behavior.
- Avoids conflating copy completion with optional checksum verification.

### Operator safety

- Review the discovered interface, complete CIDR, transfer root, peer bundle,
  and entered paths before apply or copy.
- TCP 5201 has no persistent listener; the speed-test server exits after one
  client.
- Copy operations never request rsync deletion, and verification is dry-run
  only.
