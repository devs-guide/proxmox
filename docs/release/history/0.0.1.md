## 0.0.1

The initial tagged release established a published bootstrap path for Proxmox
VE 6.4 on archived Debian Buster. It combined a streamed shell entrypoint,
GitHub Pages-hosted Ansible artifacts, release-specific variables, and a
managed Python 3.11 / ansible-core 2.15 environment.

### Scope

- Release range: initial repository history through `0.0.1`
- Target lane: Proxmox VE 6.4 / Debian Buster
- Published entrypoint: `bootstrap/release.6.4.sh`
- Managed runtime: Python 3.11 and ansible-core 2.15
- Important exclusion: later unified Python 3.12 / ansible-core 2.20 runtime

### Highlights

- Added the first remotely published Proxmox bootstrap flow.
- Added archive-aware Debian and Proxmox repository configuration.
- Added a managed Ansible handoff after the distro-compatible bootstrap stage.
- Added web-certificate regeneration and LAN-oriented access policy.

### Added

- Release-specific bootstrap playlists and merged base/Buster/release vars.
- Python 3.11 build support, a managed Ansible virtual environment, pinned
  `community.general`, and passlib support.
- PVE proxy certificate regeneration with hostname and IP SANs.
- Dedicated legacy Node/NVM handling.

### Changed

- Generalized Debian playbooks so release folders could reuse shared tasks.
- Moved runtime preparation into the release-local playbook and switched from
  temporary system Ansible to the managed environment after handoff.
- Used archived Debian, security, and Proxmox repositories appropriate to the
  historical 6.4 lane.

### Fixed

- Fixed early Pages publication, variable merging, network-module, package,
  SSH-access, UFW, certificate, and legacy Node compatibility failures.
- Reduced bootstrap lockout risk by making initial LAN access explicit.

### Operator workflow and safety

This historical lane bootstraps with the system-compatible tools first, then
hands off to the managed runtime. Operators must review archived repositories,
LAN access, passwords, SSH policy, and certificate identity before using it on
a host. Later releases supersede this runtime contract.
