## 0.0.3

Release 0.0.3 added the first end-to-end manual Proxmox VLAN/data-bridge
workflow. It introduced hardware discovery, operator NIC selection, staged
network writes, ifupdown2 validation, live apply, and rollback protection.

### Scope

- Release range: `0.0.2..0.0.3`
- Target lane: Proxmox manual VLAN/data-bridge workflow
- Published entrypoint: `setup.vlan.sh`
- Core playbooks: hardware discovery, Proxmox VLAN management, and feature vars

### Highlights

- Added a dedicated Proxmox network-feature namespace and interactive runner.
- Persisted discovered hardware and operator selections before mutation.
- Published the complete runner/playbook graph through GitHub Pages.
- Added post-apply bridge attachment verification and rollback safeguards.

### Added

- Physical NIC, bridge, and management-path discovery.
- `preflight`, `write`, and `apply` modes for the selected data bridge.
- Dry-run ifreload validation and configuration backup/rollback.
- Pages publication and runtime validation for the feature graph.

### Changed

- Replaced implicit interface assumptions with ranked, operator-confirmed NIC
  selection and persisted facts.
- Standardized network mutation around staged configuration and management-path
  preservation.

### Fixed

- Fixed physical NIC and bridge-member parsing, setup UI stability, YAML
  loading, null bridge membership, duplicate interface declarations, and
  management-path conflicts.
- Fixed apply-time cases where a selected NIC remained detached after reload by
  verifying attachment and remediating before rollback.

### Operator workflow and safety

Operators review discovered management and data roles before writing. The
runner stages and validates configuration, applies it with management-path
guards, verifies live bridge membership, and restores the prior file when the
accepted state cannot be reached.
