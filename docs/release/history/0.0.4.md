## 0.0.4

Release 0.0.4 added the first Debian LXC plus Samba workload path to the
Proxmox feature workflow. It combined host-side container creation and mount
attachment with container-side Debian preparation and a LAN-oriented Samba
service.

### Scope

- Release range: `0.0.3..0.0.4`
- Target boundary: Debian LXC creation and Samba workload setup
- Published entrypoints: `setup/lxc/debian.sh` and `setup/lxc/samba.sh`
- Important exclusion: later isolated DATA-Link, mapped-ACL, and hardened
  single-share behavior introduced after this historical release

### Highlights

- Added interactive Debian template, storage, bridge, address, mountpoint, and
  base-profile selection.
- Added deterministic Buster-through-Trixie template policy with official URL
  fallback.
- Added container-side mount discovery and macOS-oriented Samba setup.
- Expanded publication and validation coverage for LXC runtime dependencies.

### Added

- Host-side LXC creation, bind-mount preparation, startup, and runtime checks.
- Container-side Debian update, package, access, and SSH preparation.
- Samba package installation, share rendering, listener checks, and local
  browse validation.
- Shared Debian netboot and SSH policy references.

### Changed

- Split the feature into host-side container creation and container-side Samba
  configuration.
- Standardized an ultra-lean unprivileged Debian appliance profile.
- Mapped selected host mounts into `/media/...` container paths.
- Persisted selected share capabilities instead of assuming every path was
  writable.

### Fixed

- Fixed empty selection serialization, Debian template fallback, missing
  published SSH policy, runtime Python selection, mountpoint preparation,
  scalar rootfs handling, and in-container mount visibility.
- Fixed static IPv4 normalization and gateway validation before `pct create`.
- Fixed selected-share propagation, anonymous guest defaults, and browse
  validation in generated Samba configuration.

### Operator workflow and safety

Operators select and review the container template, resources, bridge,
addressing, and mountpoints before creation. Mount targets are prepared and
verified inside the running container before Samba publishes selected paths.
This historical release predates the stricter 0.0.7 network and firewall
boundary and should not be read as that later policy.
