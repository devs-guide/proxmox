## 0.0.2

Release 0.0.2 unified the managed Ansible bootstrap across the supported
Proxmox 6.4 and emerging 9.x lanes. It standardized the target runtime on
Python 3.12 and ansible-core 2.20.5 while retaining a distro-compatible
controller path for initial bootstrap and handoff.

### Scope

- Release range: `0.0.1..0.0.2`
- Target lanes: Proxmox VE 6.4/Buster and Proxmox VE 9.1/Trixie
- Managed target interpreter: `/opt/ansible/py312/bin/python`
- Managed controller environment: `/opt/ansible-venv`
- Pinned controller: ansible-core 2.20.5

### Highlights

- Added the PVE 9.1/Trixie bootstrap lane.
- Shared Python 3.12 and Ansible 13 policy across release lanes.
- Kept old-system-Python bootstrap checks separate from post-handoff modules.
- Standardized package and SSH-user policy across releases.

### Added

- Trixie repository, package, and runtime guards for PVE 9.1.
- Shared managed-runtime handoff and repair behavior.
- Publication drift checks and release-scoped package catalogs.

### Changed

- Replaced release-specific runtime drift with one managed Python and
  ansible-core contract.
- Kept `udftools` canonical in the shared Debian package catalog.
- Derived `AllowUsers` from shared account definitions across both lanes.
- Refreshed package catalogs and re-enforced selected account policy on reruns.

### Fixed

- Fixed old-Python package-fact failures by using distro-compatible checks
  before handoff.
- Fixed recursive/stale virtual-environment bootstrap behavior.
- Fixed PVE-safe package selection, Trixie repositories, and shared SSH-user
  resolution.
- Reduced unnecessary reruns in users, network, and certificate playbooks.

### Operator workflow and safety

The controller starts with tools compatible with the host distribution and
uses the managed interpreter only after the handoff marker is valid. Package
and repository changes remain release-scoped so a modern lane does not inject
unsupported packages into the archived lane.
