## 0.0.5

Release 0.0.5 promoted the managed Proxmox runtime, network automation,
reusable LXC layers, and recoverable VM restore workflow. It retained the
Proxmox VE 6.4/Buster compatibility lane while making Proxmox VE 9.1/Trixie
the current host setup lane.

### Scope

- Release range: `0.0.4..0.0.5`
- Supported lanes: Proxmox VE 6.4/Buster and Proxmox VE 9.1/Trixie
- Feature boundary: bootstrap/runtime, host and guest networking, reusable LXC
  capabilities, and local/remote QEMU restore
- Important exclusion: storage provisioning, isolated Samba ingest, and GPU
  passthrough remained later release work

### Highlights

- Preferred native Trixie Python for the controller while retaining the
  managed target runtime and pinned ansible-core 2.20.5 contract.
- Added persisted network preflight, plan, apply, and verification artifacts.
- Split LXC setup into common, Debian, users, network, Samba, Node, and Codex
  layers.
- Added resumable local and remote QEMU restore with durable JSON state.
- Added exact-candidate CI, immutable Pages artifacts, guarded feature
  publication, and live post-publication checks.

### Added

- `setup/network.sh` and its network preflight/update/verification graph.
- Reusable LXC users, network, and Codex entrypoints.
- Host-side Codex installation through `setup/cli.codex.sh`.
- VM restore orchestration plus SSH synchronization, archive inspection,
  rsync transfer, and temporary storage lifecycle helpers.
- Release, runtime, restore, and publication validators.

### Changed

- Configured Trixie and Proxmox no-subscription repositories before package
  updates while removing conflicting enterprise/Ceph sources.
- Used native Python when policy-compatible and kept modules on the managed
  target interpreter after handoff.
- Standardized published shell helpers on explicit `.sh` paths and declared
  dependencies.
- Separated validation from guarded Pages deployment so ordinary pushes and
  pull requests did not publish.

### Fixed

- Fixed PVE 9 repository order, publication paths, and native-Python handoff.
- Fixed LXC variable serialization, SFTP policy, user separation, sudo
  membership, and wrapper imports.
- Fixed network runner default detection and validation behavior.
- Fixed missing validation dependencies and release overlays.
- Hardened restore state transitions, check-mode service handling, interrupted
  stage recovery, and runner-Python selection.
- Ensured Pages deployment consumes only the exact validated artifact.

### Operator workflow and safety

The repository still shipped editable LAN-oriented example accounts and
network policy in this historical release. Operators were required to replace
example passwords, users, subnets, ports, and repository choices before
production use. Restore operations persisted state at each stage and required
preflight and verification before advancing or resuming.
